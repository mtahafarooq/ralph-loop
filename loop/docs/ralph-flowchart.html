01 Follow one shuttle pass

One process. One task. One return.

ralph-once.sh is the unit to understand first. It validates the package, opens one agent process, lets that fresh context complete at most one ready task, and returns control.

./loop/ralph-once.shRALPH_AUTO_COMMIT=0 ./loop/ralph-once.sh

The complete walkthrough is visible below. Enable JavaScript for guided stepping and route highlighting.

Wrapper configuration

Choose the agent contract

The default adapter calls cmd -p --yolo. --agent chooses another executable, repeated --agent-arg options replace the defaults, and --no-commit disables automatic commits.

Preflight

Require the durable inputs

The wrapper refuses to start without PROMPT.md, prd.json, and progress.txt. A missing input fails before an agent process exists.

Validation gate

Prove the backlog is executable

  • Task fields and IDs have the required shape.
  • IDs and branch names are unique.
  • Dependencies exist, do not point to self, and form no cycle.
  • Every task branch passes Git ref validation.

Host boundary

Verify where and how work will run

The inferred or overridden project root must exist, and the configured agent executable must be available. The wrapper changes to the host project root before invoking it.

Fresh process

Start with a clean context window

The wrapper reads the stable prompt, appends runtime paths and commit mode, creates a timestamped log, then starts exactly one coding-agent process. Output streams to the terminal and the log.

Durable memory

Reconstruct context from artifacts

The new agent reads the PRD, append-only progress notes, recent Git history, repository guidance, and established project checks. No previous conversation is required.

Deterministic selection

Choose at most one ready task

A task is ready when passes is false and every dependency passes. The lowest numeric priority wins; document order breaks ties.

Decision point

Continue, complete, or stop blocked

  • If all tasks pass, emit <promise>COMPLETE</promise>.
  • If incomplete tasks exist but none is ready, emit <ralph>BLOCKED:no-ready-task</ralph>.
  • If one task is ready, continue only with that task.

Task execution

Change only what the task requires

The agent checks working-tree safety, enters the task branch only when safe, avoids unrelated work, and proves every acceptance criterion with the project’s established tests, type checks, lint checks, builds, or manual verification.

Evidence handoff

Persist facts, not conversation

Success updates only the selected task, appends a structured progress entry, and optionally creates one atomic commit. Failure keeps passes: false, records actionable context when safe, and creates no success commit.

Process boundary

Emit a marker and return

A successful task emits <ralph>ITERATION_COMPLETE:TASK-ID</ralph>. A failure emits <ralph>FAILED:TASK-ID</ralph>. The wrapper returns the child status and never begins another task.

Choose what the fresh context discovers
One task passes, durable state changes, and control returns with an iteration-complete marker.

03 Add the supervisor

Repeat only while progress is trustworthy.

ralph.sh does not implement tasks. It supervises fresh single runs, checks the protocol, and refuses to continue when evidence is missing or contradictory.

./loop/ralph.sh 10

Bounded execution

Require a positive maximum

The positional number or RALPH_MAX_ITERATIONS defines the ceiling. Invalid and zero values stop before work begins.

Initial gate

Reject an invalid backlog

The same structural and dependency validator runs before the outer loop creates a lock or starts an agent.

Concurrency guard

Only one supervisor may run

An atomic directory lock under loop/.runtime/ prevents concurrent loops. A trap removes only this process’s lock on exit or handled interruption.

Progress evidence

Record the PRD checksum

Before each iteration, the supervisor fingerprints prd.json. That snapshot later proves whether the agent persisted backlog progress.

Iteration N of maximum

Launch a new single-run process

Each pass invokes ralph-once.sh as a separate process and tees combined output to the iteration log.

First stop check

Honor the child exit status

A nonzero result stops immediately and propagates the failure. The supervisor does not retry a broken iteration.

Protocol stop

Stop on blocked or failed work

A BLOCKED or FAILED marker requires human attention. Automatic repetition would only reproduce or compound the problem.

Completion proof

Trust marker and data together

A completion marker succeeds only when every PRD task actually passes. A marker that contradicts the backlog is treated as protocol failure.

Post-run gate

Reject corrupted state

Before considering another pass, the supervisor reruns the PRD validator against the agent’s persisted changes.

Progress proof

Compare the checksum

If prd.json did not change, the loop stops. A claimed success without changed task state is not enough to justify another iteration.

Protocol proof

Require iteration-complete output

A changed PRD still needs <ralph>ITERATION_COMPLETE:TASK-ID</ralph>. Missing output means the result is malformed.

Safe repetition

Discard context, keep evidence

Only a valid, changed backlog plus an iteration-complete marker allows a new process to start. The previous agent context is not reused.

Hard ceiling

Stop with work remaining

After the final allowed pass, the supervisor exits nonzero if tasks remain. It never silently extends its own budget.

✓

Complete

The marker and PRD agree that every task passes.

!

05 Recover deliberately

A stop is information, not an invitation to bypass checks.

Resolve the underlying state with one supervised run before returning to repetition.

  1. Read terminal output and the latest file under loop/.runtime/logs/.
  2. Inspect git status before touching branch or working-tree state.
  3. Read the selected task’s notes and the latest progress entry.
  4. Resolve unsafe changes, validation failures, or blocked dependencies manually.
  5. Keep passes: false until every acceptance criterion succeeds.
  6. Run ralph-once.sh again before resuming ralph.sh.

Protocol reference

<promise>COMPLETE</promise>All tasks pass; the supervisor verifies the PRD.
<ralph>ITERATION_COMPLETE:TASK-ID</ralph>One verified task completed and state changed.
<ralph>BLOCKED:reason</ralph>Human intervention is required before repetition.
<ralph>FAILED:TASK-ID</ralph>The selected task did not satisfy its checks.
